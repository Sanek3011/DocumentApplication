# Сборка и запуск
- Склонировать себе на пк
- Собрать jarку, используя mvn clean package.
- В директории documentApplication выполнить скрипт docker-compose командой docker-compose up. БД и приложение автоматически поднимутся, накатится схема БД, будет доступно по адресу localhost:8080. Доступ к БД по порту 5434. Дефолтные логин postgres пароль postgres
- Утилита для генерации отчетов в отдельном модуле DocumentGenerator. В папке resource, в файле parameter.txt указываете число N, после чего запускаете App.class из idea или java -jar из консоли. Адрес развернутого приложения documentApplication уже установлен. По дефолту генерируется 5 документов. Обращается по localhost:8080/api/v1/documents/batch
- Для удобства и наглядности подрубил свагер. Доступен по адресу http://localhost:8080/swagger-ui/index.html


  ## Логи
  - Во время прихода на сервер документа или пачки - кол-во пришедших
  - Сохранение успешно/неуспешно. Если пачкой - то ход выполнения сохранения пачки
  - Отправка пачки на согласование или утверждение. В случае отправки фоновым процессом в логе указывается название инициатора в начале лога. Пример: [SUBMIT-WORKER]
  - Логирование обработки пачек согласования/утверждения. Ход выполнения обработки, в случае неуспешной обработки - вывод номера документа и причины по которой документ не был обработан.
 
  # Комментарий автора

  - В тз не указано каким образом нужно валидировать или узнавать initiator потому для обращения к апишкам согласования и утверждения нужен кастомный хедер X-Initiator. Для внутренних вызовов ничего не нужно, submit-worker, approve-worker и тестовые указываются автоматически.
  - Требование "Если запись в реестр создать не удалось, утверждение документа должно быть
отменено." - я бы сделал через транзакции, используя transaction и propogation.mandatory дабы все выполнялось атомарно в одной транзакции. Это бы сделало невозможным запись в таблицу без реальной смены статуса, как и смену статуса без записи в реестр
- "что бы вы поменяли, чтобы обработка одного запроса уверенно работала с 5000+ id" - Добавил бы пул потоков (5-10) и обрабатывал документы батчами.
- "как бы вы вынесли реестр утверждений в отдельную систему (отдельная БД или
отдельный HTTP-сервис)." - отдельный сервис со своей БД, общение через месседж брокер, дабы был независим от жизненного цикла документа
